# Accelerated 10-Day Codex Proficiency Sprint

**Purpose:** reach hands-on productivity quickly, not merely read documentation. Allow **90–120 minutes/day** if available; otherwise split each day across two sessions. This schedule is an intensive alternative to, not a replacement for, full lesson mastery.

**Daily rhythm:** 15 min concept → 60–80 min hands-on → 15 min review/journal. Each day produce a commit, note, verified test, or diagram. Make changes on safe branches and use existing projects only when authorized.

| Sprint day | Activities | Tangible proof |
| --- | --- | --- |
| 1 | Lessons 1–2: ChatGPT vs Codex; sign in; read-only repo tour | Repository map and setup notes |
| 2 | Lessons 3–4: Git branches; first tiny change | Reviewed commit and evidence |
| 3 | Lessons 6–8: precise prompts, agent planning, AGENTS.md | Task template and verified instructions |
| 4 | Lessons 9 and 13: reproduce a bug; write regression tests | Passing regression check |
| 5 | Lessons 10 and 14: review and merge PR | Merged low-risk PR |
| 6 | Lessons 11–12: architecture and full feature | Feature branch and demo |
| 7 | Lesson 15: preview deploy, logs, rollback | Smoke test and recovery notes |
| 8 | Lessons 17–18: threat model, code/dependency security checks | Triage report with justified findings |
| 9 | Lessons 18–19: patch verified issue and compare agents | Security PR and comparison table |
| 10 | Lesson 20: capstone release | Release note, evidence, next backlog |

## Fastest route to mastery

- **Do:** small complete features, reviews, testing, bug reproduction, debugging and deployment.
- **Learn enough code to supervise:** control flow, functions, JSON, error handling, APIs, dependencies, and simple tests; learn language syntax as needed.
- **Measure:** time to verified completion, bugs introduced, review findings, test pass rates, and rework—not number of lines written.
- **Apply Daybreak Blue:** pursue approval in parallel; the secure SDLC skills are useful **without** access. No security practice requires Daybreak approval.

## Weekly review prompts

1. Can I independently create and recover a safe branch?
2. Can I recognize when the agent failed to validate an assumption?
3. Can I explain what the change does and how to test/revert it?
4. What took the most time? Can I improve the prompt or testing setup?
5. Did any task involve credentials, production services or unapproved security scope? If so, stop and obtain authorization.
